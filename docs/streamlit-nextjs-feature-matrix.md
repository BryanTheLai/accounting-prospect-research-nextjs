# Streamlit → Next.js feature matrix

**Code snapshot:** 2026-10-05. This compares the two user-facing apps in the workspace: the Streamlit app and the Next.js app. The Python dispatcher sidecar is a supporting process for the Next.js app, not a third product.

**Scope:** Active UI behavior reachable from Streamlit’s four mounted tabs and the Next.js desk/routes. A helper, script, README claim, or unmounted function is not counted as an active UI feature. “Present” describes code in this snapshot; it does not mean a campaign was run or email was sent.

## Visual First

```text
Streamlit app (one user-facing app)
  ├─ Outbound Cockpit ── campaign setup, recipient selection, dispatch, deliverability
  ├─ Campaign Studio ─── prompt presets + YC explorer + CSV/XLSX import
  ├─ Phone & WhatsApp ── callable queue, disposition, follow-up aids
  └─ Mailboxes & Settings ─ DNS files, IMAP, suppression list
             │
             └────────────── local SQLite (`leads.db` by default)

Next.js app (second user-facing app)
  ├─ Overview / Prospects / Call / Campaigns / Settings
  ├─ /yc /import /email-preflight /playbooks /mailboxes /activity
  └─ API routes ── local Python dispatcher sidecar ── dispatcher
```

The default Streamlit and Next.js database paths resolve to the sibling `accounting-prospect-research/leads.db`. Streamlit’s `config.py` uses its own `BASE_DIR / "leads.db"`; the Next.js web app and Python sidecar honor `OUTBOUNDER_DB_PATH`. If that variable redirects only the Next.js processes, the apps can use different databases. [Streamlit database path](../../accounting-prospect-research/config.py#L24-L25), [Next.js web database path](../web/lib/db.ts#L5-L18), [Next.js Python database path](../config.py#L24-L25), [Next.js runtime notes](../web/README.md#L5-L14).

## Sourcing, campaign setup, and imports

**Sourcing** is finding/qualifying companies and recording evidence about them. **Ingestion** is writing chosen directory or file rows into the prospects table and assigning a campaign. In either app, importing a company does not establish that a person or inbox exists, approve that record for outreach, or send a message.

## Dormant code and concrete remaining gaps

The Streamlit source header describes Template Studio and Master Archive, but neither is an active tab. `render_template_studio_tab()` is defined but not called by `app.py`; the archive is loaded into `archive_df` but no active page renders it. They are dormant code, not active Streamlit features. [Header/archive load](../../accounting-prospect-research/app.py#L1-L7), [archive load](../../accounting-prospect-research/app.py#L464-L466), [four mounted tabs](../../accounting-prospect-research/app.py#L490-L516), [unmounted Template Studio](../../accounting-prospect-research/ui_campaign_manager.py#L743-L845).

Remaining differences in the current source snapshot:

1. **Streamlit YC safety:** its active YC import guesses `founder@<domain>` and can reset an existing row’s status. Next’s YC import is add-only, leaves person/contact fields blank, and skips existing IDs.
2. **Streamlit campaign timezone:** only Next has per-campaign schedule storage and enforcement. Streamlit has one global weekday window whose control is labeled SGT, but its effective timezone is `DISPATCH_TIMEZONE` (default `America/New_York` unless configured externally). It does not enforce California 09:00–18:00 for YC campaigns. This is a concrete gap against the requested YC send policy.
3. **Streamlit outreach gates:** its active dispatcher does not require Approved for Outreach or fresh exact-email MX/source evidence. Its personal-test button can reach real SMTP while the global live flag is off. Next requires matching evidence no older than 30 days and has explicit live confirmation; its MX/source preflight still cannot establish mailbox existence.
4. **Email discovery:** both active apps find email candidates from public company pages. Next limits discovery to a small set of pages on the recorded company domain and saves only after an explicit selection; a changed address atomically invalidates the old preflight. Streamlit adoption remains transient. Neither app’s current process verifies individual inbox existence.
5. **Templates and experiments:** neither active UI edits template bodies/spintax. Both can preview a recipient; Next’s preview is read-only, switches between A/B, and renders spintax, but does not predict the random dispatch assignment. Next now persists each prospect’s chosen template for the same campaign/template pair across retries and dispatcher restarts. It has no variant performance analysis; starting a later retry creates a new run ID and does not automatically resume a stopped queue.
6. **Deliverability operations:** Next has mailbox CRUD, manual suppression additions, per-mailbox caps/delay settings, warmup visibility/enforcement, manual DNSBL checks plus DNS guidance/downloads, and a bounded manual read-only IMAP scan. It still has no SMTP handshake, background inbox scan, or suppression removal action. The DNSBL check lets the operator choose a domain and preserves unavailable-provider status; Streamlit checks its configured primary domain and may label all-unlisted timeouts clean. The tools do not gate sends. Next’s DNS sample uses DMARC `p=none` and warns that its BIND template targets `openclosehq.com`; Streamlit’s guide shows `p=reject`.
7. **Call extras:** Next now has contact editing, all ten call outcomes, persisted notes/duration/follow-up, campaign-scoped metrics, recent history, company website/LinkedIn shortcuts, six objection responses, and an editable copy-only one-page follow-up text draft. The follow-up draft is not saved or sent.
8. **Classifier parity:** Next hiring detection uses explicit notes/source evidence and can miss unrecorded job posts. Email-tier and government classifiers differ. Dispatch eligibility is intentionally independent of Prospect-page filters.

The Streamlit-only behaviors with direct outbound consequences are a **single global weekday send window** (UI label: SGT; effective timezone: `DISPATCH_TIMEZONE`, default `America/New_York`, with no per-campaign setting) and a **personal-preview SMTP exception that can send to a personal/admin address while the global live flag is off**. Next instead enforces each campaign’s saved local schedule, rechecks recipient eligibility immediately before live `sendmail`, and does not expose that personal-preview exception. ## Reliability boundary

Streamlit has a shorter local route: its UI calls its Python dispatcher directly. The Next.js app uses its browser UI and API routes plus a loopback Python sidecar, adding a process/HTTP/token boundary. The sidecar keeps dispatch control out of the browser and performs candidate/queue checks; Streamlit has direct-send paths. This structure alone does not prove either app has better uptime or fewer runtime failures; these source trees contain no comparative uptime/error dataset.
